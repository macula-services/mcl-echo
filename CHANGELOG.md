# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- `scripts/mcl_echo_call` prints the whole route before it calls, not just the
  station and procedure: station host, the station node id the dial is pinned
  to, the procedure, the realm in name and tag form, this caller's own node id,
  and the payload term with its local `erlang:external_size/1`. A fan-out is
  read back from six terminals at once, and a session that reports the route it
  meant to take rather than the one it took makes the whole run unreadable. The
  realm is computed with `macula_realm:id/1` and the payload printed from the
  same macro the call sends, so neither line can drift from what happened.
- Echo calls go through `macula_direct_dial:call/6` with a recording `dial_io`,
  so the run prints the route the SDK actually walked: each advertisement
  lookup (`find_records`), each station endpoint lookup (`find_record`) and each
  station call (`call_station`), in order. `macula:call/5` never names the
  station it resolved to, so a harness logging its own argument was logging the
  request and calling it an answer. The station handed to `call_station` is the
  resolved one, pinned as `expected_node_id` on that dial. The seam replaces the
  SDK's defaults rather than merging with them and refuses a wrong key set or
  arity with `function_clause` at call time, which a clean compile does not
  catch, so the map's shape is checked against a dummy pool with no mesh
  contact; the seam also owns its own trace table, because a missing one
  surfaced as a `badarg` several frames deep inside `macula_direct_dial`.
- The caller node id is on the banner because it **is** the rate-limit key.
  `macula_station_link:with_caller/2` merges the wire-authenticated caller into
  the payload only when the payload is a map, so the map payload is what gives
  each caller its own 20-per-10s bucket instead of the shared 300-per-10s global
  one. A `rate_limited` result is only readable next to the id it was counted
  against.
- The caller script refuses instead of guessing on two preconditions, both of
  which turn into six separate debugging sessions when they fail quietly: an
  uncompiled tree now exits 3 by name rather than letting a literal `-pa` glob
  fail deep in the boot, and a missing `mise` exits 4 rather than running
  whatever `erl` is first on `PATH`. `.tool-versions` pins the OTP these beams
  and their NIFs were built with and it is not that `erl`.

### Notes

- `verify => webpki` in the caller is inert in macula 11.4.0:
  `macula_peering_conn:start_dial/1` reads only `alpn` and `timeout_ms` off the
  dial target and hardcodes `{verify, none}` into the QUIC dial. Merged, not
  released, not running: macula's trunk fixes it in `f3575b25`, where
  `start_dial/1` passes `dial_opts(Target)`, but that commit carries no tag and
  is not an ancestor of `v11.4.0`, which is what hex serves and what this
  service runs. The station is named on this path by the required D16
  `expected_node_id` handshake pin instead, and TLS server verification is not
  the control there. The UNVERIFIED-dial warning on every run is expected; the
  option is kept so the intent is recorded.

## [0.1.0]

### Added

- `scripts/mcl_echo_call` (`mcl_echo_call`), the terminal caller: a plain
  escript, not a test, carrying the io.macula seed pin and the realm trust
  pin. It retries genuinely transient failures (`timeout`,
  `temporary_relay_failure`) while a fresh route warms up, and fails fast
  and visibly on a resolution error, so a not-yet-admitted procedure stays
  obvious instead of looking merely slow.
- `scripts/mcl_echo_demo` and `mcl_echo_demo_svc`, the hand-run demo driver
  (`start`/`stop`/`status`). The service under it is a plain long-running
  process rather than an eunit case: no window, no budget, no timeout, so a
  rehearsed clip cannot be cut short by a test harness. `MCL_BOX` overrides
  the box label.
- `scripts/mcl_echo_withdraw` (`mcl_echo_withdraw`), a plain-erl tombstone
  CLI. The reset path uses it instead of the realm's mix toolchain, and the
  shared io.macula pins live in one header
  (`apps/mcl_echo/include/mcl_echo_io_macula.hrl`) so the seed and the realm
  key are stated once.
- `test_live` REAL-realm mode: mcl-echo claims, the realm admits, and the
  real D25 chain resolves. `MCL_LIVE_DEMO` holds the service up for a
  hand-run flow (`MCL_LIVE_DEMO_TIMEOUT_S` overrides the one hour default;
  20 minutes was measured too tight for a rehearsed clip).
- The scaffold, generated by `rebar3 new mcl_service`: an OTP release that
  boots on `mcl_om`, joins the mesh, and answers `/health` on 8461.
- `mcl_echo_service`, the six-callback `mcl_om_service` contract, announcing
  no capability and requesting no authority because it can do nothing yet.
- Unit tests asserting the contract's shape, including that the mesh-facing name
  and the reported version match the application's own.
- `Containerfile` building an alpine image, with macula's QUIC NIF compiled from
  source rather than fetched against a foreign libc.
- `deploy/docker-compose.yml`, the service's own run contract.
- CI: `lint-and-test` on every push and pull request, `build-and-push` to
  the registry on `main` and on `v*` tags, publishing both `:latest` and the semver
  tag.
- `.tool-versions` pinning `erlang 28.4.2` for local asdf-based development,
  matching the `erlang:28` already pinned in `Containerfile` and CI. Without
  it, a machine whose asdf global points elsewhere (29.0.6, in this case)
  compiles against a dependency's (khepri's) deprecated bare-`catch` syntax,
  which `warnings_as_errors` turns into a hard build failure that has nothing
  to do with this service's own code.
- `mcl_echo_mesh_rpc`: advertises `io.macula.echo` -- the hello-world
  target every Macula SDK's own quickstart README calls -- on the all-zero
  realm, hardcoded rather than configurable (every quickstart calls from an
  identity that has joined nothing yet; a realm mismatch here is silent and
  would recreate the exact bug this service exists to fix). Built on
  `macula_response` (supervised per-call responses), not `mcl_om`'s own
  org-namespaced capability mechanism, since that could never produce the
  bare literal procedure name every SDK already hardcodes.
- `mcl_echo_limiter`: a fixed-window request-rate limiter. `io.macula.echo`
  is deliberately public and unauthenticated, and the platform's own inbound-
  call dispatch carries no rate limiting or backpressure at any layer (traced
  directly). Keyed by caller NodeId when the platform provides one -- which it
  only does when the payload is a map, so most real traffic (every SDK
  quickstart sends a bare text payload) falls back to one shared global
  counter. A hard payload-size cap (measured via `erlang:external_size/1`, so
  it bounds every payload shape, not just binaries) is enforced in the
  handler itself, ahead of the rate check.

### Changed

- **One org per service, decoupled from the realm.** The org is the repo
  name (`mcl-echo`) and the realm stays `io.macula`, so the wire procedure
  is `mcl-echo/echo`. The previous convention derived the realm tag from the
  org name by sha256, so the two could not differ. That coupling is gone:
  the realm binds the org at admission and issues this node's D25
  delegation there, which is why `mcl_echo_service` now asserts both values
  are well formed rather than asserting one is a hash of the other.
- Takes `mcl_om` 0.2's boot-time provider-authorization claim: the service
  asks the realm for its own authorization at boot, over the mesh, by its
  wire-authenticated identity and with no credentials. `MCL_SERVICE_NAME`
  and `MCL_BOX` travel in the claim payload as the informational labels the
  realm operator sees on the pending row.
- `io.macula.echo` is now advertised through the standard
  `mcl_om_capabilities` path (`mcl_echo_service:capabilities/0`)
  instead of a hardcoded, one-shot `macula_response:advertise/6` call
  wrapped in its own supervised gen_server (`mcl_echo_advertiser`,
  removed). `mcl_om_capabilities` registers the org-qualified
  `Org/Name` and nothing else (`advertise_one/6`): the 11.x wire refuses a
  procedure with no org namespace (`no_org_namespace`), so the wire name
  here is `mcl-echo/echo` and the bare `io.macula.echo` literal the 10.x
  quickstarts hardcode is NOT served by this deployment. (The dual
  bare-plus-org advertise this entry first described was the 10.x
  behaviour; `mcl_om_capabilities`'s own moduledoc still describes it.)
  The standard path gets a
  periodic re-advertise and TTL for free, closing the actual root cause
  of a live incident: a boot-time-only advertisement that a mesh DHT scan
  found had zero live records for `io.macula.echo`, because nothing ever
  refreshed it. `capabilities/0` asserts that realm and org are both
  configured and well formed before returning the capability list (a
  32-byte realm tag; an org matching `^[a-z0-9][a-z0-9._-]*$` and not the
  `_` placeholder), since `mcl_om_capabilities` resolves one realm and one
  org for the whole batch from live identity rather than from a hardcoded
  constant, and a mismatch in either is silent on the wire. It does NOT
  check that the realm is a hash of the org.

### Fixed

- **The box label reached the wire as a charlist.** `os:getenv/1` returns a
  list, and the realm desk's Node column came back empty for every claim.
  Converted to binary at the boundary. Found live, on the desk.
